# Test feeder (NDS project)

Imitates the Capture AddOn for single-machine verification of the Delay
Buffer Service (the "next test" row of the test topology diagram):

    TestFeeder ──TCP:9166──> DelayBufferService ──NinjaTrader.Client.dll──> DelayedFeed / NQDELAY

## Function

- Connects to the Delay Buffer Service at 127.0.0.1:9166.
- Sends synthetic events in the established line format
  `TYPE|INSTRUMENT|PRICE|SIZE|PROVIDER_TIMESTAMP_TICKS|CAPTURE_TIMESTAMP_TICKS`,
  generated by a random walk on the NQ 0.25 tick grid starting at 23500.00.
- Each price step produces three events: Bid, Ask, Last. Default rate:
  2 steps/second (6 events/second); overridable as the first command-line
  argument, e.g. `TestFeeder.exe 10` for 10 steps/second.
- Once per second the console prints `[HH:mm:ss] price=... sent=...` —
  the verification reference: the printed price must appear on the NQDELAY
  chart exactly Delta later (30 seconds in the development configuration).

## Installation and build

1. Download `TestFeeder.zip` and unzip it into `C:\Dev\NDS\src\`.
2. Verify the expected result:

       C:\Dev\NDS\src\TestFeeder\TestFeeder.sln
       C:\Dev\NDS\src\TestFeeder\TestFeeder\Program.cs

3. Open the solution in Visual Studio 2022 and build (Ctrl+Shift+B).
   No NinjaTrader reference is required; the default Any CPU platform is
   correct for this project.
4. Commit to the Git repository.

## Verification procedure (single machine, Delta = 30 s)

Preconditions:
- NinjaTrader 8 running with **DelayedFeed as the ONLY active connection**
  (Live must be disconnected — the External Data Feed connection is
  exclusive by design).
- A 1-tick chart for NQDELAY is open.
- TickReceiver is not running (port 9166 conflict).

Order of starting matters:

1. **Start the Delay Buffer Service**
   (`DelayBufferService\bin\x64\Debug\DelayBufferService.exe`).
   Expected: "Connected to NinjaTrader." then "Ingestion listener active on
   port 9166."
   Note: the Capture AddOn inside NinjaTrader will also connect to the
   service within 5 seconds and may deliver live events if the Live
   connection were active — with Live disconnected it captures nothing,
   so it does not interfere with this test.
2. **Start the test feeder**
   (`TestFeeder\bin\Debug\TestFeeder.exe`).
   Expected: "Connected. Sending synthetic events." and one price line per
   second.
   Note: the service accepts one sender at a time; if the Capture AddOn
   occupies the connection, the feeder reports a connection failure —
   in that case disable the Capture AddOn or stop/restart the service and
   start the feeder within 5 seconds.
3. **Observe for at least 2 minutes.** Success criteria:
   - Service status line: `received` grows immediately; `released` starts
     growing approximately 30 seconds after the feeder start; thereafter
     `received - released` stays approximately constant (about 30 seconds
     of events); `late`, `malformed`, `pushErrors` remain 0.
   - NQDELAY chart: first ticks appear approximately 30 seconds after the
     feeder start; each price printed by the feeder at time T appears on
     the chart at approximately T + 30 s.
4. **Stop**: Ctrl+C in the feeder first, then Ctrl+C in the service.
   The service stops releasing on shutdown (it never releases early);
   remaining queued events are intentionally not pushed.

## Result interpretation

- This test proves: line parsing, FIFO queue, delay enforcement, sustained
  pushing through NinjaTrader.Client.dll, and chart construction from the
  delayed stream.
- Combined with the earlier verifications (Capture AddOn → TickReceiver;
  TickPusher → DelayedFeed), only one element remains unproven afterwards:
  both pipeline halves running simultaneously against live data, which
  requires the two-machine configuration.
